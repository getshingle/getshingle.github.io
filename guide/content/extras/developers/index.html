Extras

For developers

How Shingle works

Shingle is one bash script of under 400 lines, plus templates. It runs with bash 3.2 (macOS), newer bash (Linux) and Git Bash (Windows), and needs only the standard tools find, sed, awk, base64 and cksum.

Folders

build.sh       the build
site.conf      settings, read as bash
content/       pages: .html (or .md with the markdown extension)
static/        copied to dist/ as it is
templates/     layout.html, header.html, footer.html
assets/        base.css, script.js and icons/*.svg
themes/        <name>/theme.css, chosen by THEME in site.conf
extensions/    add-ons; a folder whose name starts with _ is off
dist/          the result; emptied on each build except hidden files such as .git

What a build does

  1. Empties dist/, keeping hidden files, so dist/ can be a Git repository of its own.
  2. For an extension seen for the first time (no content/<name>/ yet), copies its example/ to content/<name>/ and adds its menu link to site.conf.
  3. Reads site.conf (Windows line endings are removed first).
  4. Copies static/ and the extensions' static/. Joins assets/base.css, extensions/*.css, the extensions' style.css and the theme into assets/site.css, and the scripts into assets/site.js, each with a version number for caching.
  5. Turns each icon into {{ICON_<NAME>}} and the logo into {{LOGO}}.
  6. Makes a page from each file in content/; other files are copied. A folder with an _index file belongs to an extension and is skipped.
  7. Runs each extension's build, then each extension's finish.

Pages

content/index.html          → /
content/about.html          → /about/
content/legal/terms.html    → /legal/terms/
content/shop/index.html     → /shop/   (with its pictures next to it)
content/404.html            → /404.html

The header goes between --- lines, or between <!-- and --> lines if you want the file to stay valid HTML. Each field becomes {{PAGE_<FIELD>}}. The layout uses title, description, image (a JPG or PNG for link previews) and robots.

Values and the line rule

Pages and templates can use any variable as {{NAME}}: everything in site.conf, {{EMAIL}} and {{PHONE}} as links (the plain values are {{EMAIL_ADDRESS}} and {{PHONE_NUMBER}}), {{ICON_GITHUB}}, {{LOGO}}, {{YEAR}} and the PAGE_ values. Values are HTML-escaped when they are read from a header.

Templates have no if-statements. One rule replaces them: a line whose values are all empty is left out. A phone line in the footer disappears when PHONE is empty.

Templates

The page frame is templates/layout.html, header.html and footer.html. An extension's templates are in extensions/<name>/templates/; to change one, copy it to templates/<name>/ and edit the copy. Your copy wins, and updating the extension does not overwrite it.

Links

Write links from the site's root: href="/about/", src="/img/photo.jpg".

  • LINKS="files" (the default) rewrites them after the build, for example to ../about/index.html. The site then works from a folder on your computer, on any web server and in a subfolder such as a GitHub Pages project site.
  • LINKS="web" keeps them as they are, for shorter addresses on a web server. To look at the result, run python3 -m http.server -d dist 8080 and open http://localhost:8080.

404.html is shown for any wrong address, at any depth, so its links always start at the root, with the path from SITE_URL in front when the site lives in a subfolder.

Write an extension

extensions/<name>/
  extension.sh     required
  templates/       its templates
  style.css        wrapped in @layer extensions { … }
  script.js        added to site.js
  static/          copied to dist/
  example/         copied to content/<name>/ the first time
  README.md

extension.sh is sourced by the build. It can set:

MENU_LINK="Recipes"    # added to MENU in site.conf the first time, as /recipes/
MENU_LIST=LEGAL        # optional: add it to another list instead
build() { …; }         # runs after the pages are built
finish() { …; }        # runs at the very end; PAGES lists every address

Code shared by several extensions lives in extensions/*.sh and is loaded first. collection.sh lists entries for the blog, news, team, careers and portfolio:

MENU_LINK="Recipes"
build() {
  LIST_SORT=desc LIST_PER_PAGE=12 LIST_FEED=true LIST_IMAGE_FILE=cover
  collection
}
item_hook() {    # optional, runs for every entry
  ITEM_SERVES=${FM_serves:+Serves $FM_serves}
}

An entry is content/<name>/<key>_<slug>.html or a folder with index.html. The key (a date or a number) sorts the entries; the slug is the address. _index.html holds the list page's header, and its per_page, sort, pages and feed win over the defaults.

In item_hook, the header is in FM_<field> (in order in FM_KEYS) and the text in BODY. Templates get ITEM_<FIELD>, ITEM_URL, ITEM_TITLE_LINK, ITEM_DATE, ITEM_DATE_TEXT, ITEM_IMAGE, ITEM_BODY, and JSON_<FIELD> for schema.json. The list templates are list.html, card.html, item.html, pager.html and schema.json. Helpers return their result in REPLY: html, json, field <file> <key>, date_text, email_link, phone_link, social_links.

Write a theme

A theme is themes/<name>/theme.css. It sets the color, font and size tokens; anything else in it wins over the template's styles, because the template's CSS is in layers and the theme is not. Two lines in its first comment are read by the build:

Fonts: https://fonts.googleapis.com/css2?family=…    or "none"
Browser color: #ffffff

Other files next to theme.css, such as fonts, are published in /assets/; preview.jpg and README.md are not.

Check your work

  • shellcheck -x build.sh extensions/*.sh extensions/*/extension.sh
  • The Nu HTML Checker for the pages in dist/.

Source code

Shingle lives in four repositories in the getshingle organization on GitHub:

  • shingle: the template, exactly what shingle.zip contains.
  • extensions: blog, portfolio, news, team, careers and the others.
  • themes: the extra themes.
  • getshingle.github.io: this guide, the examples, and the tools that test everything on Linux, macOS (with its bash 3.2) and Windows and publish this website.
